New Game → opponent selection: a refactor rev 2

Revised after your feedback. The two big shifts: the strategy editor becomes one progressively-disclosed form (no more “free composition” vs “by algorithm” split — that’s two mental models for one job), and custom opponents become server-persisted named profiles that sit right alongside the built-in presets.

Locked from rev 1: editor opens as a slide-over side panel (not a nested modal) · saved profiles are server-persisted alongside presets · the flat seat <select> becomes grouped seat rows · AiPresetInfo.description gets surfaced.

1  Your feedback, and what it changes

You saidChange in this revision
“[Time and iterations] can both be true at the same time.” Rev 1’s single time/iterations radio was wrong. Both limits can be active together (whichever fires first ends the search — matches SearchConfig today). New framing: a Stop conditions block with two optional limits; the UI just guarantees at least one stays on, so the “both off” invalid state still can’t occur.
“A ‘light’ algorithm selection and a ‘per axis’ approach means two mental models.” The mode: "free" | "params" toggle is deleted. One form: pick an algorithm, see its few primary knobs, and each of the four axes is a row you expand only if you want to override it. Free axis composition is the same form, expanded — not a separate mode.
“Consider expanding config_ir to have more structure that helps the UI.” The plan now moves display metadata into the schema itself: axis_schema() / strategy-algorithms emit label, help, and tier (primary / advanced) per field and variant. The UI renders generically from that — no hand-maintained label map to drift. See §3.3 and decision 1.
“A notion of expanding as needed, along with reasonable defaults.” Progressive disclosure is now the core idea, not a footnote. Everything unexpanded shows its effective default as a summary line; you only ever touch what you care about.

2  Goal

  • “Human vs. Strong AI” is one glance, one click per seat.
  • Tuning an opponent is one mental model that gets deeper as you scroll/expand — never a fork between “easy mode” and “real mode”.
  • A tuned opponent is a named, saved, server-side profile — reusable across seats, games, and sessions, and indistinguishable from a built-in preset at the point of use.
  • No invalid states, no raw Rust identifiers as labels.

How the one-model form works

  • Top of form = the 90% case. Name, stop conditions, algorithm, its 2–3 primary knobs. A player who just wants “a strong Othello bot that thinks 2s” never scrolls past here.
  • “Fine-tuning” = the old free composition, but each axis is a collapsed row showing its effective value (“UCB1 (default)”). Expand a row to override it with the full variant picker + fields. Collapsed rows contribute their default.
  • No mode toggle. There is exactly one form; depth is opt-in per axis. The thing people actually want to do — nudge one axis — is one expand, not a mode switch that re-defaults everything.
  • Labels + help come from the schema (§3.3). “Decisive-move (win/loss aware)”, not decisive_move. Hover help on every field.
  • “Based on” seeds the whole form from a preset’s resolved params, so you start from something that plays well.
  • Slide-over: right-docked panel, ~420px, its own scroll. The board stays visible behind it; no modal-over-modal.

3.3  Schema-carried display metadata (the config_ir change)

Rather than a hand-maintained wire-labels.ts that silently falls behind the Rust schema, the schema endpoints grow optional presentation fields. Additive and backward-compatible — older clients ignore them.

5  Build sequence

1

Slide-over shell + extract the editor no wire

Move StrategyConfigEditor out of the inline seat loop in GameShell.tsx into a right-docked slide-over opened by “Edit…”. Behaviour otherwise unchanged. Covered by the existing GameShell.test.tsx mocked-env harness.

2

Seat rows + grouped dropdown + descriptions no wire

Replace the flat <select> with a seat-row component; group options; wire AiPresetInfo.description into labels and the summary line. Mirror/Swap helpers.

3

Collapse the editor to one progressive form no wire

Delete the mode toggle and switchToFree/switchToNamed. Render: stop-conditions block (2 optional limits, ≥1 enforced), algorithm + its tier:"primary" knobs, then per-axis expander rows that fall back to defaults when collapsed. AlgorithmFields’ activeNames/withDefaultsFilled logic is reused for the “effective value” summaries.

4

Schema display metadata Rust + wire

Add optional label / help / tier to config_ir_schema::axis_schema() and the strategy-algorithms payload; extend the TS AxisFieldSchema/AxisVariantSchema/TunerParameter types. Renderer consumes them with a title-cased-tag fallback. Additive; UI step 3 works without it and improves once it lands.

5

Server-persisted user profiles Rust + wire

User preset store (<data-dir>/opponents/*.json), folded into GET /ai_presets with an origin: "builtin" | "user" flag; POST/PUT/DELETE for user ones. UI: “Saved” group, save/duplicate/delete in the slide-over. Seat refs for saved profiles become plain {preset: id}.

6

Polish no wire

Slide-over transitions, focus management, keyboard, invalid-profile badges (§6 risk), empty-state for the Saved group.

Steps 1–3 remove the confusion with zero backend work and can ship as a unit. Steps 4–5 are the “more schema structure” and “server-persisted” investments and each stand alone.

6  Risks & failure modes

Effective-default summaries can mislead

A collapsed axis row claims “UCB1 (default)”. If the real default for the chosen algorithm is something else, the summary lies. Mitigation: derive every summary from the same withDefaultsFilled pass that builds the submitted spec — the summary and the payload read from one source, so they cannot disagree.

Saved profile references a removed variant/field

A persisted spec can name an axis variant or field deleted by a later Rust change. Mitigation: validate against the live AxisSchema on load; flag invalid profiles with a “needs review” badge, keep them out of seat assignment until re-saved. Never silently drop or crash.

Schema metadata is a second source of truth for labels

Even in Rust, label/help can rot relative to the field’s actual behaviour. Mitigation: keep them terminal (no logic depends on them), and add a schema test asserting every tier:"primary" field has a non-empty label+help so the important ones can’t regress to blank.

Migration: existing in-flight custom seats

Nothing persists custom seat configs today, so there is no stored data to migrate. The only compat surface is the wire {preset:"custom", custom} shape, which stays valid. Built-in preset ids are unchanged.
